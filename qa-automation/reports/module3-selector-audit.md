## Крок 4. DevTools-діагностика: неправильний пароль

### Чекліст DevTools

Сторінка/сценарій: логін з неправильним паролем (goit@gmail.com + asd123asd)

1. Сценарій відтворено вручну до потрібного стану: [x]
2. Стан елемента в Elements: з'являється в DOM після сабміту (toast UnauthorizedError, role="alert")
3. Console вище рядка введення: немає критичних помилок застосунку [x]
4. Селектор повідомлення: `$$('[role="alert"]')` → length = 1
5. Network (login, порт 4040): статус **401**, час ~**60–90 мс**
6. Умова появи: з'являється після сабміту форми з невалідним паролем (відповідь 401)

**Висновок:** [x] готово для тесту

## Крок 5. CSS-селектори реєстрації

### Реєстрація (/auth/register)

| Перевірка | Результат |
|-----------|-----------|
| `$$('input[type="password"]').length` | 2 |
| `$$('#password').length` / `$$('#repeatPassword').length` | 1 / 1 |
| `$$('label > input[type="checkbox"]').length` | 1 |
| `$$('input[type="checkbox"] + span').length` (сусід) | 1 |
| `$$('input[type="checkbox"]:checked').length` до кліку | 0 |
| `$$('input[type="checkbox"]:checked').length` після кліку | 1 |

### Головна

| Перевірка | Результат |
|-----------|-----------|
| `$$('button:disabled').length` | 1–2 (залежить від сторінки/фільтра) |
| `$$('button:disabled[aria-label="previous page"]').length` | 1 |

## Підсумкова таблиця

| Елемент | Сторінка | Обраний CSS-селектор | Чому саме він |
|---------|----------|----------------------|---------------|
| Поле email | /auth/login | `#email` | Унікальний id, пріоритет 2 |
| Поле пароля | /auth/login | `#password` | Унікальний id |
